# Keil C51 Standard 8051 (Winbond / Nuvoton W78 Series) Project & SBOM Solution

<p align="right">
  <b><a href="README.md">繁體中文 (Traditional Chinese)</a></b> | <b>English</b>
</p>

This repository provides a production-grade Keil C51 firmware project template targeting **standard 8051 architecture microcontrollers with Zero-BSP and standard 8051 headers only** (`<REG52.H>`, `<INTRINS.H>`), along with an automated **Software Bill of Materials (SBOM)** generator driven by build-artifact evidence.

---

## 1. Core Background & Challenges

### The Blind Spot of Traditional SCA Tools on Standard 8051
Conventional Software Composition Analysis (SCA) and SBOM tools (such as Syft, Trivy, cdxgen, and Snyk) primarily scan modern package management manifests (e.g. `package.json`, `pom.xml`, `requirements.txt`, `CMakeLists.txt`, or CMSIS-Pack). However, in classical bare-metal 8051 development:
1. **Zero Manifests**: The codebase typically consists only of `STARTUP.A51` and `.c` source files with `#include <REG52.H>`.
2. **No External BSP**: The firmware does not depend on third-party vendor SDKs or open-source middleware.
3. **Implicit Binary Dependencies**: Although engineers write pure standard C, the Keil Linker (`BL51.exe`) automatically links Keil's closed-source runtime helper library (`C51S.LIB`) and internal routines (`?C_INIT`, `?C?UIDIV`, `?C?SLCMP`) into the final binary based on the memory model (e.g., Small Model).

When traditional scanners inspect this directory, they find no manifests and output an **empty SBOM** (0 components). This fails to meet compliance standards under the **EU Cyber Resilience Act (CRA)**, **US Executive Order 14028 (NTIA Minimum Elements)**, and industrial/automotive cybersecurity mandates that require full binary component traceability and SHA-256 cryptographic hashes.

---

## 2. Solution: Build-Artifact-Driven Reverse SBOM Extraction

This project bypasses source manifest limitations by analyzing build evidence generated by the Keil C51 toolchain during compilation and linking:

```text
[Keil µVision .uvproj] ───────► Hardware Target (W78E052D MCU, RAM/ROM specs)
[Compiler .lst & Source] ────► Recursive Standard Headers (C51\INC\REG52.H, INTRINS.H & notices)
[Linker .m51 Map File] ──────► Implicit Runtime Libraries (C51\LIB\C51S.LIB & ?C_INIT, ?C?UIDIV)
[STARTUP.A51 & main.c] ──────► Application Source Files (Cryptographic SHA-256 hashes)
[Keil TOOLS.INI & .exe] ─────► Toolchain Provenance (Suite V9.61 + C51 V9.60.7.0, BL51 V6.22.4.0)
         │
         ▼
[tools/generate_c51_sbom.py]
         │
         ├──► CycloneDX v1.5 JSON  (sbom/sbom.cdx.json)
         ├──► SPDX v2.3 JSON       (sbom/sbom.spdx.json)
         └──► Markdown Audit Report (sbom/SBOM-REPORT.md)
```

## 4. Prerequisites & Environment Setup

Before building firmware and generating SBOMs, ensure your Windows host meets the following prerequisites:

| Software | Minimum Version | Purpose | Installation & Verification |
| :--- | :--- | :--- | :--- |
| **Operating System** | Windows 10 / 11 (64-bit) | Host OS for running Keil and PowerShell scripts | - |
| **Keil C51** | C51 V9.60+ (V9.61 Recommended) | Provides compiler (`C51.exe`), assembler (`A51.exe`), linker (`BL51.exe`), HEX converter (`OH51.exe`), and standard 8051 headers | Download and install **C51 Development Tools** from [Arm Keil Official Site](https://www.keil.com/demo/eval/c51.htm) (Evaluation or Licensed version).<br>Default path: `C:\Keil_v5\C51` or `%LOCALAPPDATA%\Keil_v5\C51`. |
| **Python** | Python 3.10+ | Runs the SBOM extraction engine and unit tests | 1. Download via [Python.org](https://www.python.org/downloads/) or run Windows package manager:<br>`winget install Python.Python.3.10`<br>2. **Important**: Check **"Add python.exe to PATH"** during installation.<br>3. **Zero pip Dependencies**: Built purely with Python standard libraries; **no `pip install` required**. |

### Verify Environment
Open PowerShell and run:
```powershell
# Verify Python version
python --version

# Verify Keil C51 registry entry
Get-ItemProperty "HKLM:\SOFTWARE\WOW6432Node\Keil\Products\C51" -ErrorAction SilentlyContinue
```

## 5. Quick Start Guide

This project supports both **GUI IDE integration** and **Headless CLI automation**:

### Mode A: Windows PowerShell Headless Build (Recommended for CI/CD)
Run the automated build script from the repository root:
```powershell
powershell -ExecutionPolicy Bypass -File .\build_and_sbom.ps1
```
The script will automatically:
1. Locate the Keil C51 toolchain from the Windows registry or default installation paths.
2. Invoke `A51.exe`, `C51.exe`, `BL51.exe`, and `OH51.exe` to build the firmware, generating `.hex` and `.m51` with relative-path space protection.
3. Execute `generate_c51_sbom.py` to produce `sbom/sbom.cdx.json`, `sbom/sbom.spdx.json`, and `sbom/SBOM-REPORT.md`.

### Mode B: Keil µVision GUI Integration (Auto-update on F7)
1. Open `project\w78_std_8051.uvproj` in Keil µVision.
2. The project is pre-configured with a Post-Build hook in `Options for Target -> User -> After Build/Rebuild` under `Run #1`:
   ```text
   python ..\tools\generate_c51_sbom.py --project-dir .
   ```
3. Whenever you press **F7** (Build Target) or Rebuild in the IDE, Keil automatically updates all SBOM outputs in the `sbom/` folder upon build completion.

### Mode C: Standalone SBOM Extraction
If the project has already been built in Keil and you only wish to re-generate the SBOMs:
```powershell
python tools\generate_c51_sbom.py --project-dir project --out-dir sbom
```
