# 概念解說：如何判斷軟體物料清單 (SBOM) 是否合規？

本篇概念解說深入探討國際資安法規（如美國 NTIA 最小元素要求、歐盟網路韌性法案 CRA、ISO/IEC 5962 等）如何定義「合規的 SBOM」，以及針對傳統嵌入式微控制器韌體（如標準 8051）的特殊審查準則。

---

## 1. 什麼是「合規」的 SBOM？

一份合規的 SBOM 不僅僅是一份文字清單，它必須是**機器可讀（Machine-Readable）**、**語意標準化**，且能夠被自動化脆弱性掃描器（如 VEX、CVE 資料庫）解析的正式文件。

當前國際上最權威的合規依據包含：
1. **美國 NTIA 最小元素（NTIA Minimum Elements for SBOM）**：源自美國白宮行政命令 EO 14028，定義了 SBOM 必須具備的 7 大基礎資料欄位與流程要求。
2. **歐盟網路韌性法案（EU Cyber Resilience Act, CRA）**：要求所有在歐盟境內銷售的數位產品（包含各類嵌入式硬體與物聯網裝置）必須提供完整、可追溯的軟體物料清單。
3. **國際標準組織規範**：**ISO/IEC 5962:2021** 正式將 SPDX 納為國際標準。

---

## 2. NTIA 定義的「7 大最小資料元素」

無論採用 CycloneDX 還是 SPDX 格式，合規的 SBOM 必須 100% 覆蓋以下 7 個資料欄位：

```
┌────────────────────────────────────────────────────────┐
│               NTIA 7 大最小必備元素                    │
├────────────────────────────────────────────────────────┤
│ 1. 供應商名稱 (Supplier Name)                          │
│ 2. 組件名稱 (Component Name)                           │
│ 3. 組件版本 (Version of the Component)                 │
│ 4. 唯一識別碼 (Unique Identifiers: PURL / CPE)         │
│ 5. 相依性關係 (Relationship: DependsOn / Contains)     │
│ 6. 產製者與工具資訊 (Author / Tool of SBOM Data)       │
│ 7. 產生時間戳記 (Timestamp: ISO-8601 UTC)              │
└────────────────────────────────────────────────────────┘
```

如果一份 SBOM 缺少時間戳記、沒有明確定義組件間的依賴關係（Relationship），或者缺少供應商資訊，在自動化法規檢核時將直接被判定為**不合格**。

---

## 3. 嵌入式韌體特有的四大深層合規要求

對於沒有套件管理器的傳統 8051 或裸機專案，國際稽核員在審查時有更嚴苛的特定標準：

### 準則一：嚴禁「空包彈 SBOM」（Non-Empty Components）
- 很多自動化 SCA 工具因找不到 `package.json` 或 `CMakeLists.txt`，輸出的組件數為 0。
- **合規判定**：空 SBOM 視同「未提供 SBOM」，屬於嚴重違規。本專案透過解析 `.m51` 與 `.uvproj` 成功建立真實組件樹。

### 準則二：必須揭露隱性二進位相依（Implicit Binary Inclusions）
- 即使原始碼未手動引用第三方庫，編譯器/連結器自動打包進韌體的閉源執行期函式庫（如 `C51S.LIB`）也是潛在弱點的載體。
- **合規判定**：必須列出 `C51S.LIB` 及其內部運算模組（如 `?C_INIT`、`?C?UIDIV`）。

### 準則三：強制包含加密防偽雜湊（Cryptographic Hashes）
- 韌體交付時通常為編譯後的 `.hex` 或 `.bin` 二進位檔。
- **合規判定**：SBOM 必須提供對應二進位產物的 SHA-256 雜湊，讓設備使用者或主管機關能使用雜湊驗證晶片內部的程式碼是否與 SBOM 描述完全一致。

### 準則四：工具鏈可追溯性（Toolchain Provenance）
- 符合安全軟體開發框架（NIST SP 800-218 SSDF）要求，記錄編譯此韌體所使用的工具鏈真實版本與執行檔雜湊（如 `C51.exe V9.60.7.0`、`BL51.exe V6.22.4.0`）。

## 4. 本專案合規對照總結

本專案產出的 SBOM 經自我檢核與規格審查：
1. **規格版本**：CycloneDX v1.5 與 SPDX v2.3。
2. **NTIA 7 大要素**：100% 滿足。
3. **二進位完整性**：提供所有標頭檔、執行期庫與 Hex 檔之 SHA-256 雜湊。
4. **法律合規**：具備直接提供給歐盟 CRA 合規審查或客戶供應鏈安全稽核之法定效力。
